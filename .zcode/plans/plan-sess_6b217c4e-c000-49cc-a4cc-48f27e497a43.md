# AdAstra 代码精简方案（平衡档）

## 分析结论概览

项目整体架构健康：`shared` 是纯叶节点、`three`/`astronomy-engine` 完全封闭在 engine 层、无 import 环、8 个运行时依赖 + 11 个开发依赖全部在用（零冗余）。真正的体积热点是数据文件（`stars.yaml` 62KB）而非代码。

**代码层面的主要问题是"过度拆分"和少量死代码**，集中在：单函数小文件、只有测试引用的死函数、config 8 个微文件、i18n 动态键的 9 处 `as MessageKey` 强转、以及少量未消费的返回成员。

> 注：探索代理有 3 处误判，已用 grep 实测纠正，**以下不做**：
> - 不删 `scripts/catalog/bright-stars-v3.yaml` —— 它被 `tests/brightStarsCoverage.test.ts` 引用；
> - 不收紧 `skyMath.ts` 的 `localSiderealHours`/`fillHorizonMatrix` 等导出 —— 它们被 `tests/skyMath.test.ts`、`tests/locateSkyTarget.test.ts` 覆盖，去 export 会破坏测试；
> - 不删 `useObserver.ts` 的 `resolveObserver` 导出 —— 被 `tests/appConfig.test.ts` 引用。

## 改动清单

### A. 删除死代码（零生产引用，已实测确认）

1. **`src/engine/performance/pixelRatio.ts`** + **`tests/pixelRatio.test.ts`** —— `decidePixelRatio` 生产零调用，渲染循环里 `renderer.getPixelRatio()` 恒为 1，整套自适应分辨率逻辑从未接入。
2. **`src/shared/ui/LoadingPanel.tsx`** —— 零消费；同步删除 `src/shared/ui/index.ts:2` 的导出、`src/shared/ui/StatusPanel.module.css` 的 `.loading` 类（`.panel` 仍被 `ErrorPanel` 使用，保留）。
3. **`src/engine/render/skyProjection.ts` 的 `viewDirectionFromNdc` 函数**（117-124 行）—— 生产零调用，仅 `tests/skyProjection.test.ts` 用；删除函数 + 该测试里的 2 处断言（第 11、19 行），其余断言保留。
4. **`src/engine/performance/frameStats.ts` 的 `averageMs` getter**（34-37 行）—— 无调用者，`snapshot()` 已返回 `averageMs` 字段。

### B. 合并单调用者小文件

5. **`src/engine/astronomy/bodySnapshotRequest.ts`（31 行）→ 并入 `attachAstroWorker.ts`**：`shouldRequestBodySnapshot` + `BODY_SNAPSHOT_MIN_INTERVAL_MS`/`BODY_SNAPSHOT_LOOKAHEAD_MS` 移入，删除独立文件与 `tests/bodySnapshotRequest.test.ts`（纯节流判断，由 worker 集成行为覆盖）。
6. **`src/engine/render/bodyLimb.ts`（8 行）→ 内联进 `bodyLayer.ts`**：`brightLimbAngle` 移入 `bodyLayer.ts`（唯一调用点 99 行），删除独立文件与 `tests/bodyLimb.test.ts`。

### C. 合并 config 目录（8 文件 99 行 → 1 文件）

7. 新建 **`src/config/index.ts`**，合并 `timeline.ts`、`cardinals.ts`、`eclipticPoles.ts`、`playbackSpeeds.ts`、`quickViews.ts`、`defaultLayers.ts`、`layerToggles.ts`、`quickTargets.ts` 的全部导出（含 `QuickViewPreset`、`LayerToggleDef` 类型与 `satisfies` 写法，保持不变）。删除 8 个原文件，更新 12 处 `@/config/xxx` import 为 `@/config`。

### D. 消除 i18n 动态键强转（用户已确认方案）

8. `src/i18n/types.ts` 的 `Translate` 改为函数重载：保留 `(key: MessageKey, ...) => string`（静态键严格校验），新增 `(key: string, ...) => string`（动态键宽松签名）。
9. `src/i18n/locale.tsx` 的 `lookup` 参数类型 `MessageKey` → `string`（运行时行为不变，动态键本就按字符串查找）。
10. 移除 9 处 `as MessageKey`：`SkyOverlayLabels.tsx`(2)、`ObjectCard.tsx`(1)、`LayerSection.tsx`(1)、`ViewSections.tsx`(1)、`QuickNav.tsx`(1)、`TimeDeck.tsx`(2)、`ErrorPanel.tsx`(2)、`names.ts`(1)。

### E. 清理冗余返回成员

11. `useSkyView.ts` 删除 `onViewChange` 别名（与 `setView` 同一函数），`App.tsx:35,140` 改为直接传 `setView`。
12. `usePlayback.ts` 返回值删除未消费的 `setIsPlaying`。
13. `useObserver.ts` 返回值删除未消费的 `activeCityIndex`。
14. `src/i18n/index.ts` 删除未消费的 `detectLocale`、`interpolate` 再导出（仅 locale.tsx 内部使用）。

### F. 配置清理

15. `tsconfig.json` 删除 `allowImportingTsExtensions: true`（代码无 `.ts` 扩展名导入）。
16. 本地删除 `dist/` 目录（`git ls-files dist` 已确认 0 个被跟踪文件，且为过期旧星表产物；不影响 git 历史）。

## 不改动的部分（保持现状，避免破坏测试或引入行为风险）

- Worker 协议层的 `type` 字段冗余、`App.tsx` 的 `bodyMagnitudes` void hack、`bodyInterpolation` 的模块级单例状态、`syncLayerVisibility`/`updateSkyCamera` 的内联、`lucide-react` 内联 SVG —— 这些属于激进档或收益低，本方案不动。

## 验证方式

- `npm run lint`（oxlint）确认无未使用导入/变量残留；
- `npx tsc --noEmit` 确认类型（重点验证 i18n 重载签名后静态键仍能报错、动态键不再强转）；
- `npm test`（vitest）确认删除死代码与合并文件后剩余 37-4=33 个测试全绿。

预计净删约 15 个文件、120+ 行，无行为变化。
